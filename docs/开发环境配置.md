### Qt 版本下限说明

`CMakeLists.txt` 中使用了 `qt_policy(SET QTP0004 OLD)`，该策略由 **Qt 6.8** 起提供（定义于
`Qt6Qml/lib/cmake/Qt6Qml/Qt6QmlMacros.cmake`），因此 **Qt 最低 6.8**；
工程构建、调试、打包均以 **Qt 6.11.0 + MinGW 13.1.0** 为基准验证，建议新机保持一致。

## 2. 新电脑安装清单

1. **Qt 在线安装器** → 选 **Qt 6.11.0**：
   - `MinGW 64-bit`（桌面，`win64_mingw`，内含 GCC 13.1.0 工具链）
   - `Android arm64-v8a`（仅安卓开发需要）
   - Developer and Designer Tools：`Qt Creator 19.x`、`CMake`、`Ninja`
2. **Android**（仅安卓开发需要）：SDK（build-tools 36.0.0 / platform android-36）+ **NDK r27c** + **JDK 17**。
3. **克隆仓库**：`git clone git@github.com:CharlieCRX/servoV6.git`
   - `external/googletest` 已在仓库内，无需额外拉取；
   - `external/asio` 被 `.gitignore` 忽略，首次 CMake 配置会自动从 GitHub 下载
     （`FetchContent … GIT_TAG asio-1-28-0`）。**离线环境**可从旧电脑直接拷贝
     `servoV6/external/asio/` 整个目录，CMake 检测到即跳过下载。

## 4. 新机验证构建（命令行等价于 VS Code 任务）

```powershell
$env:PATH = "D:/develop/Qt6/Tools/mingw1310_64/bin;D:/develop/Qt6/6.11.0/mingw_64/bin;$env:PATH"

# 1) 配置（等价 .vscode/tasks.json -> cmake-configure）
& "D:/develop/Qt6/Tools/CMake_64/bin/cmake.exe" -S . -B build -G "MinGW Makefiles" `
    -DCMAKE_BUILD_TYPE=Debug -DCMAKE_CXX_STANDARD=20 `
    -DCMAKE_MAKE_PROGRAM="D:/develop/Qt6/Tools/mingw1310_64/bin/mingw32-make.exe" `
    -DCMAKE_C_COMPILER="D:/develop/Qt6/Tools/mingw1310_64/bin/gcc.exe" `
    -DCMAKE_CXX_COMPILER="D:/develop/Qt6/Tools/mingw1310_64/bin/g++.exe" `
    -DCMAKE_PREFIX_PATH="D:/develop/Qt6/6.11.0/mingw_64" `
    -DSERVO_V6_UNIFIED_CONTROL=ON -DSERVO_V6_ENABLE_VNEXT_UDP=ON

# 2) 编译 GUI（等价 cmake-build-appservoV6；产物 build/appservoV6.exe）
& "D:/develop/Qt6/Tools/CMake_64/bin/cmake.exe" --build build --target appservoV6 --parallel 8

# 3) 编译并运行单元测试
& "D:/develop/Qt6/Tools/CMake_64/bin/cmake.exe" --build build --target unit_tests --parallel 8
& "D:/develop/Qt6/Tools/CMake_64/bin/ctest.exe" --test-dir build --output-on-failure
```

Windows 桌面构建会在生成后自动执行 `windeployqt --compiler-runtime --qmldir .`，
把 Qt 运行库部署到 `build/`（`SERVO_V6_DEPLOY_WINDOWS_RUNTIME=ON`，见 `CMakeLists.txt` 末尾）。

## 5. 已知环境注意点

- **不要混用 MSVC**：工程默认 Kit 为 MinGW；用 MSVC 需另建 Kit 并重新配置。
- **Android 工具链**：Qt Creator Android Kit 的 `CMAKE_TOOLCHAIN_FILE` 指向
  `android-ndk-r27c/build/cmake/android.toolchain.cmake`，`ANDROID_ABI=arm64-v8a`。
- **并行度**：旧机使用 `--parallel 8`（`servo.cmakeBuildParallel`），新机按 CPU 核数调整。
- **GCC 版本**必须与 Qt 预编译二进制匹配（MinGW 13.1.0 对应 `win64_mingw` 包）；
  混用其他 MinGW（如 8.1/11/15）会链接报错。
- **JDK**：本机 PATH 上的 `java` 是 JDK 26，而 Android 构建实际使用 `JAVA_HOME=D:\develop\jdk-17.0.16.8-hotspot`；
  新机请安装 JDK 17 并正确设置 `JAVA_HOME`（Qt 19.0.0 的 `androiddeployqt`/Gradle 不支持过新 JDK）。
- **编译被中断会留下损坏的 `.obj`**：MinGW `make` 只按时间戳判断是否重编，
  半途被杀掉的 `gcc` 会留下 `nm` 报 `file format not recognized` 的坏对象文件，
  下一次构建把坏对象归档后表现为一堆 `undefined reference to ...`（曾实测踩坑）。
  处理方式：删除对应 `.obj` 或直接重跑 `cmake-clean` + `cmake-build`（删掉 `build/` 重来）。

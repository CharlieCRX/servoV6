# 摇杆适配流程规划（servoV6）

## 1. 背景与目标

servoV3 已经有一套成熟的摇杆控制逻辑（详见 `docs/architecture/servoV3摇杆控制逻辑.md`），但 servoV6 在架构上做了根本性重构（分层架构：Domain → Application/Policy → Presentation/ViewModel → QML UI），因此不能直接照搬 servoV3 的实现，需要适配到新的分层体系中。

### 1.1 核心差异

| 维度 | servoV3 | servoV6 |
|------|---------|---------|
| 总线 | Qt Signal/Slot 直连 | QML ↔ ViewModel ↔ Domain (tick-driven) |
| 点动 | `MotorCtrl::actionJog()` 阻塞线程循环 | `JogOrchestrator` 非阻塞 tick 状态机 |
| 定位 | 无（仅点动） | `AbsMovePolicy` / `RelMovePolicy` 两步操作 |
| 平台 | `#ifdef Q_OS_ANDROID` | 需支持多平台（Windows / Android） |
| 输入层 | `QGamepad` 模块 | 同样使用 `QGamepad`（Qt 6 跨平台） |

### 1.2 需求概要

1. **点动界面**：摇杆推前/右 → JOG+，摇杆推后/左 → JOG-，回中 → 自动停止
2. **定位界面**：摇杆方向键映射到触发按钮（绝对定位 GO / 相对定位 GO）

## 2. 现有架构分析

### 2.1 分层架构速览

```
┌─────────────────────────────────────────────┐
│  QML UI  (ActionControlBlock.qml)           │
│    - currentMode: 0=点动 / 1=定位            │
│    - JOG+/JOG- 按钮 → ViewModel 方法        │
│    - 绝对/相对定位 GO → triggerAbsMove/RelMove│
├─────────────────────────────────────────────┤
│  ViewModel  (QtAxisViewModel / Core)         │
│    - jogPositivePressed/Released()          │
│    - jogNegativePressed/Released()          │
│    - triggerAbsMove() / triggerRelMove()    │
│    - tick() 驱动所有 Policy                 │
├─────────────────────────────────────────────┤
│  Application Policy                          │
│    - JogOrchestrator (点动编排)              │
│    - AbsMovePolicy (绝对定位编排)            │
│    - RelMovePolicy (相对定位编排)            │
├─────────────────────────────────────────────┤
│  Domain                                      │
│    - Axis::jog(dir) / stopJog(dir)          │
│    - Axis::setAbsTarget / setRelTarget      │
├─────────────────────────────────────────────┤
│  Infrastructure (PLC Driver)                 │
└─────────────────────────────────────────────┘
```

### 2.2 点动模式现有数据流

```
QML onPressed: jogPositivePressed()
    → QtAxisViewModel::jogPositivePressed()
    → AxisViewModelCore::jog(Direction::Forward)
    → JogOrchestrator::startJog(m_axisId, Direction::Forward)
    → tick() 驱动状态机：
        EnsuringEnabled → PostEnableDelay → IssuingJog → Jogging

QML onReleased: jogPositiveReleased()
    → QtAxisViewModel::jogPositiveReleased()
    → AxisViewModelCore::jogStop(Direction::Forward)
    → JogOrchestrator::stopJog(m_axisId, Direction::Forward)
    → tick() 驱动：
        IssuingStop → WaitingForIdle → PostStopDelay → EnsuringDisabled → Done
```

### 2.3 定位模式现有数据流

```
1. 用户设置目标:
   QML NumPad onConfirmed → setAbsTarget(value)
   → AxisViewModelCore::setAbsTarget(value)
   → Axis::setAbsTarget(value)
   → consumePendingCommands() 将 SetAbsTargetCommand 下发到 PLC

2. 用户触发执行:
   QML onClicked: triggerAbsMove()
   → AxisViewModelCore::triggerAbsMove()
   → AbsMovePolicy::startAbs(m_axisId)
   → tick() 驱动状态机：
       EnsuringEnabled → TriggeringMove → WaitingMotionStart
       → WaitingMotionFinish → PostStopDelay → Disabling → Done
```

## 3. 摇杆适配方案

### 3.1 新增模块：`JoystickManager`

在 `presentation` 层新增一个独立的摇杆管理模块，负责：
- 通过 `QGamepad` API 检测手柄连接/断开
- 读取摇杆轴值（左摇杆 X/Y、右摇杆 X/Y）
- 将模拟值转化为方向信号（FORWARD / BACKWARD / NEUTRAL）
- 根据当前 `currentMode`（点动/定位）分发不同语义

```
文件结构：
  presentation/viewmodel/JoystickManager.h      ← 摇杆扫描 & 方向判定
  presentation/viewmodel/JoystickManager.cpp
```

#### 3.1.1 职责边界

| 职责 | 位置 |
|------|------|
| 摇杆硬件连接/断开检测 | `JoystickManager` |
| 轴值读取 & 死区判定 | `JoystickManager` |
| 方向映射（Forward/Backward/Neutral） | `JoystickManager` |
| 模式感知分发（点动 vs 定位） | `JoystickManager` |
| 点动流程编排 | `JogOrchestrator`（现有，不修改） |
| 定位触发编排 | `AbsMovePolicy` / `RelMovePolicy`（现有，不修改） |

### 3.2 方向映射规则

#### 3.2.1 摇杆轴定义

| 物理轴 | Qt 信号 | 方向语义 |
|--------|---------|----------|
| 左摇杆 X | `axisLeftXChanged` | 正值→右(Forward), 负值→左(Backward) |
| 左摇杆 Y | `axisLeftYChanged` | 负值→前(Forward), 正值→后(Backward) |
| 右摇杆 X | `axisRightXChanged` | 正值→右(Forward), 负值→左(Backward) |
| 右摇杆 Y | `axisRightYChanged` | 负值→前(Forward), 正值→后(Backward) |

#### 3.2.2 方向枚举

```cpp
enum class JoystickDirection {
    Forward,    // 前/右 → JOG+
    Backward,   // 后/左 → JOG-
    Neutral     // 死区/回中
};
```

#### 3.2.3 死区处理

- 死区阈值：`|value| < 0.15`（servoV3 使用 1.0，servoV6 建议调整为此经验值，对应 QGamepad 归一化范围 [-1, 1]）
- 进入死区时：发射上一个有效方向的"停止"信号（跨轴跳跃保护同 servoV3）

#### 3.2.4 跨轴跳跃保护

同 servoV3 逻辑：
```
如果当前检测到 Backward，但上一次有效方向是 Forward：
    → 先发射 ForwardReleased（停止前进）
    → 再发射 BackwardPressed（开始后退）
```

### 3.3 两种模式下的摇杆行为

#### 3.3.1 模式 A：点动模式（currentMode === 0）

**行为**：摇杆作为 JOG 按钮的物理替代

```
摇杆推前/右（Forward）
    → JoystickManager 输出 Forward
    → 调用 viewModel.jogPositivePressed()
    → JogOrchestrator::startJog(AxisId, Direction::Forward)

摇杆回中（Neutral）
    → JoystickManager 输出 Neutral
    → 调用 viewModel.jogPositiveReleased()（或对应上一个方向的 Released）
    → JogOrchestrator::stopJog(AxisId, Direction)

摇杆推后/左（Backward）
    → JoystickManager 输出 Backward
    → 调用 viewModel.jogNegativePressed()
    → JogOrchestrator::startJog(AxisId, Direction::Backward)
```

**关键约束**：
- 摇杆信号与 QML 按钮信号共享同一套 ViewModel 接口
- `JogOrchestrator::stopJog()` 自带 `AxisId + Direction` 双重防误杀
- 不需要修改 `JogOrchestrator` 内部逻辑

#### 3.3.2 模式 B：定位模式（currentMode === 1）

**行为**：摇杆方向键映射到定位触发按钮

这里需要明确的映射策略：

**方案 B1：方向映射到绝对定位 GO**

```
摇杆推前/右 → 触发 triggerAbsMove()（绝对定位 GO）
摇杆推后/左 → 触发 triggerAbsMove()（同样绝对定位 GO，方向由目标值决定）
```

> ⚠️ 该方案语义不清晰，因为绝对定位 GO 的移动方向由"当前位置 vs 目标位置"决定，而非摇杆方向。

**方案 B2（推荐）：方向映射到相对定位**

```
摇杆推前/右 → 设置正距离 + 触发 triggerRelMove()
             → setRelTarget(+stepDistance) + triggerRelMove()
摇杆推后/左 → 设置负距离 + 触发 triggerRelMove()
             → setRelTarget(-stepDistance) + triggerRelMove()
```

其中 `stepDistance` 为预设的步进距离（例如 1mm / 10mm，可在 UI 中配置）。

> ✅ 这套方案语义自然：摇杆推前 → 向前走一步，推后 → 向后走一步。
> 每次摇杆从 Neautral→Forward 触发一次相对移动，持续按住不重复触发（点动模式下是持续触发）。

**定位模式摇杆行为细化：**

| 摇杆动作 | 点动模式 (mode=0) | 定位模式 (mode=1) |
|----------|------------------|-------------------|
| 推前/右 | 持续点动前进 | 触发一次相对定位 GO（正方向） |
| 推后/左 | 持续点动后退 | 触发一次相对定位 GO（负方向） |
| 回中 | 停止点动 | 无动作（定位已触发完成，Policy 自动编排） |
| 按住不放 | 持续点动 | 仅第一次触发（边沿触发，避免连续定位） |

### 3.4 架构集成点

#### 3.4.1 `JoystickManager` 的创建与生命周期

在 `Main.qml` 或顶层 QML 中创建 `JoystickManager` 实例，作为单例管理：

```qml
// Main.qml 或顶层 Window
ApplicationWindow {
    JoystickManager {
        id: joystickManager
        currentMode: mainDashboard.currentControlMode  // 绑定当前模式
        currentAxisViewModel: mainDashboard.currentAxisViewModel  // 绑定当前轴
    }
}
```

#### 3.4.2 `JoystickManager` 与 `AxisViewModelCore` 的交互

```cpp
class JoystickManager : public QObject {
    Q_OBJECT
    Q_PROPERTY(int currentMode READ currentMode WRITE setCurrentMode NOTIFY currentModeChanged)
    Q_PROPERTY(QtAxisViewModel* currentAxisViewModel READ currentAxisViewModel
               WRITE setCurrentAxisViewModel NOTIFY currentAxisViewModelChanged)

public:
    void setCurrentMode(int mode);           // 0=点动, 1=定位
    void setCurrentAxisViewModel(QtAxisViewModel* vm);

    // tick() 由外部定时器驱动（与 ViewModel tick 同频率）
    void tick();

private:
    void pollJoystickState();                // 读取轴值，判定方向
    void dispatchJogMode(JoystickDirection dir);   // 点动分发
    void dispatchPositionMode(JoystickDirection dir); // 定位分发

    QGamepad* m_gamepad = nullptr;
    JoystickDirection m_lastDirection = JoystickDirection::Neutral;
    int m_currentMode = 0;
    QtAxisViewModel* m_currentAxisVM = nullptr;

    // 定位模式边沿检测（避免按住重复触发）
    bool m_positionTriggerArmed = true;  // 回中后重置为 true
    double m_stepDistance = 1.0;         // 步进距离 mm
};
```

#### 3.4.3 `JoystickManager::tick()` 伪代码

```cpp
void JoystickManager::tick() {
    if (!m_gamepad) return;
    if (!m_currentAxisVM) return;

    JoystickDirection dir = readJoystickDirection();

    // 跨轴跳跃保护
    if (m_lastDirection == JoystickDirection::Forward && dir == JoystickDirection::Backward) {
        dispatchRelease(JoystickDirection::Forward);
    } else if (m_lastDirection == JoystickDirection::Backward && dir == JoystickDirection::Forward) {
        dispatchRelease(JoystickDirection::Backward);
    }

    // 分发到当前模式
    if (m_currentMode == 0) {
        dispatchJogMode(dir);
    } else {
        dispatchPositionMode(dir);
    }

    m_lastDirection = dir;
}

void JoystickManager::dispatchJogMode(JoystickDirection dir) {
    if (dir == JoystickDirection::Forward) {
        m_currentAxisVM->jogPositivePressed();   // → Core::jog(Direction::Forward)
    } else if (dir == JoystickDirection::Backward) {
        m_currentAxisVM->jogNegativePressed();   // → Core::jog(Direction::Backward)
    } else {
        // Neutral: 释放上一个方向
        if (m_lastDirection == JoystickDirection::Forward) {
            m_currentAxisVM->jogPositiveReleased();
        } else if (m_lastDirection == JoystickDirection::Backward) {
            m_currentAxisVM->jogNegativeReleased();
        }
    }
}

void JoystickManager::dispatchPositionMode(JoystickDirection dir) {
    if (dir == JoystickDirection::Neutral) {
        m_positionTriggerArmed = true;   // 回中 → 允许下次触发
        return;
    }
    if (!m_positionTriggerArmed) return; // 边沿触发，避免按住重复

    m_positionTriggerArmed = false;

    double distance = (dir == JoystickDirection::Forward)
                      ? +m_stepDistance
                      : -m_stepDistance;

    // 两步操作：先设置距离，再触发
    if (m_currentAxisVM->setRelTarget(distance)) {
        m_currentAxisVM->triggerRelMove();
    }
}
```

## 4. 安全与互斥设计

### 4.1 摇杆与 QML 按钮的互斥

摇杆和 QML 按钮共享同一套 ViewModel 接口（`jogPositivePressed/Released` 等），自然的互斥由 `JogOrchestrator` 提供：

- `JogOrchestrator::startJog()` 会启动新的编排流程
- 如果已有活跃的编排，会自然覆盖（`stopJog` 防误杀仅校验 AxisId+Direction 匹配）
- **建议增强**：在 `AxisViewModelCore::jog()` 中，如果 `m_jogOrch` 处于活跃状态且方向不同，先调用 `jogStop` 停止上一个方向，再启动新方向。

### 4.2 定位模式下的互斥

- `m_positionTriggerArmed` 确保每次摇杆推一次只触发一次定位
- `isLoading` 保护：如果 Policy 正在运行（定位尚未完成），不触发新的定位
- 建议在 `dispatchPositionMode` 中增加 `!m_currentAxisVM->isLoading()` 检查

### 4.3 安全锁定 & 龙门锁定

现有的 QML 层锁（`systemLocked` + `gantryOperationLocked`）在 ViewModel 层已生效。`JoystickManager` 调用 ViewModel 方法时，这些锁自然生效。不需要在 `JoystickManager` 中重复检查。

### 4.4 弹窗禁用摇杆

servoV3 使用 `JoystickControllerManager` + 引用计数来在弹窗打开时禁用摇杆。servoV6 可以采用相同机制，或更简单地：

- 在 `JoystickManager` 中提供 `setEnabled(bool)` 属性
- QML 侧的 Dialog onOpened/onClosed 控制此属性

## 5. 实施步骤

### Phase 1：创建 JoystickManager（核心模块）

**文件**：
- `presentation/viewmodel/JoystickManager.h`
- `presentation/viewmodel/JoystickManager.cpp`

**内容**：
1. `QGamepad` 初始化与连接管理
2. 摇杆轴值读取（4 轴: leftX, leftY, rightX, rightY）
3. `readJoystickDirection()` — 综合 4 轴值判定最终方向
4. 死区判定（阈值 0.15）
5. 跨轴跳跃保护
6. `tick()` 主循环（由外部定时器驱动）

### Phase 2：集成到 QML 层

**文件**：
- `presentation/viewmodel/JoystickManager.h`（QML 注册）
- `Main.qml` 或 `MainDashboard.qml`

**内容**：
1. 将 `JoystickManager` 注册为 QML 类型
2. 绑定 `currentMode` 到 `ActionControlBlock.currentMode`
3. 绑定 `currentAxisViewModel` 到当前选中的轴 ViewModel
4. 弹窗禁用逻辑（可选，后续迭代）

### Phase 3：点动模式适配

验证路径：
```
摇杆推前 → JoystickManager → jogPositivePressed() → JogOrchestrator → 电机前进
摇杆回中 → JoystickManager → jogPositiveReleased() → JogOrchestrator → 停止
```

**无需修改现有代码**（`JogOrchestrator` / `AxisViewModelCore::jog/jogStop` 不需要改动）。

### Phase 4：定位模式适配

**文件**：
- `presentation/viewmodel/JoystickManager.cpp`（`dispatchPositionMode` 实现）

**内容**：
1. 边沿触发逻辑（`m_positionTriggerArmed`）
2. 步进距离配置（`m_stepDistance`，可通过 QML 设置）
3. 调用 `setRelTarget(distance)` + `triggerRelMove()`
4. `isLoading` 保护

### Phase 5：测试与调优

1. **单元测试**：`JoystickManager` 方向判定逻辑测试（mock `QGamepad` 轴值）
2. **集成测试**：摇杆 → 电机运动的完整链路（使用 `FakePLC`）
3. **死区阈值调优**：根据实际手柄手感调整
4. **定位步进距离配置**：添加 UI 元素让用户配置步进值

## 6. 与 servoV3 的差异总结

| 特性 | servoV3 | servoV6（新方案） |
|------|---------|-------------------|
| 输入模块 | `InputManager` | `JoystickManager`（新） |
| 信号分发 | `JoystickControllerManager` | `JoystickManager` 直接分发到 ViewModel |
| 点动执行 | `MotorCtrl::actionJog()` 阻塞线程 | `JogOrchestrator` 非阻塞状态机 |
| 定位模式 | 不支持 | 摇杆方向 → `setRelTarget + triggerRelMove` |
| 使能/掉电 | 点动前使能，停止后掉电 | 点动编排器自动管理（EnsuringEnabled → EnsuringDisabled） |
| 平台限制 | 仅 Android | 跨平台（Qt 6 QGamepad 支持 Windows/Android 等） |
| 弹窗互斥 | `JoystickControllerManager` 引用计数 | 可选：`JoystickManager.enabled` 属性 |
| 引用计数禁用 | 有 | 不继承（简化设计，弹窗通过 `enabled` 控制） |

## 7. 未决问题

1. **步进距离**：定位模式下，摇杆推一次的步进距离是多少？需要产品/业务方确认。建议默认 1mm，可通过 NumPad 配置。

2. **多摇杆同时输入**：如果用户同时推动左摇杆和右摇杆，行为如何定义？servoV3 左右摇杆独立维护方向；servoV6 当前只有一个目标轴，建议左摇杆优先（或取绝对值较大的轴）。

3. **手柄按键映射**：QGamepad 的按钮（A/B/X/Y）是否也需要映射？例如 A 键 = JOG+，B 键 = JOG-？当前规划聚焦于摇杆轴，按键映射可后续迭代。

4. **持续按住行为**：定位模式下，持续按住摇杆应该：
   - A. 仅触发一次（当前方案，边沿触发）
   - B. 持续重复触发（如每 500ms 一次）
   建议 A，由产品确认。

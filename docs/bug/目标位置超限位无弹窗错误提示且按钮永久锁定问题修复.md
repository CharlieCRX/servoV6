# 目标位置超限位无弹窗错误提示且按钮永久锁定问题修复

## 问题描述

在设置绝对/相对位置移动的 target 值时，若输入值超出软限位（如 negLimit = -100.0，用户输入 target = -150.0），后端（Domain 层 `Axis`）会拒绝该设置并返回 `false`，同时在 Telemetry 摘要中标记 `errs=1`。

### UI 表现

1. **缺少弹窗错误提示**：用户输入超限位目标后，NumPad 正常关闭，看起来设置"成功"，但实际后端已拒绝，用户无感知
2. **按钮永久不可用**：设置被拒绝后，`hasError` 变为 `true`，导致 `isReadyForTrigger` / `isReadyForSetTarget` 为 `false`，绝对定位 GO / 相对定位 GO 按钮变为灰色"不可用"状态，并且不会自动恢复

## 根因分析

### 1. ViewModel 无法透传失败信息到 UI

- `AxisViewModelCore::setAbsTarget()` / `setRelTarget()` 原返回类型为 `void`
- QML 调用后无法感知后端是否拒绝
- 用户输入超限位目标，NumPad 正常关闭，无任何错误反馈

### 2. hasError 将 Inline 错误与 Modal 错误混为一谈

- 后端拒绝超限位目标时，会在 `MoveOrchestrator` 中记录一个 **Inline** 类错误（不是致命错误，仅表示本次操作被拒绝）
- 但 `hasError` 对所有类型错误（Inline / Modal / Critical）均返回 `true`
- QML 中 `isReadyForTrigger` 条件依赖 `!viewModel.hasError`
- 结果：按钮因 Inline 错误被永久锁定，用户无法重新输入合法值继续操作

## 解决方案

### 修改文件清单

| 文件 | 修改内容 |
|------|----------|
| `presentation/viewmodel/AxisViewModelCore.h` | `setAbsTarget` / `setRelTarget` 返回 `bool`；新增 `hasBlockingError()` 方法 |
| `presentation/viewmodel/AxisViewModelCore.cpp` | 实现 `hasBlockingError()`，`setAbsTarget` / `setRelTarget` 返回 `bool` |
| `presentation/viewmodel/QtAxisViewModel.h` | 新增 `hasBlockingError` Q_PROPERTY 声明 |
| `presentation/qml/components/TargetSettingsPopup.qml` | "保存"按钮检查返回值，失败时弹出 errorDialog |
| `presentation/qml/blocks/ActionControlBlock.qml` | NumPad onConfirmed 检查返回值并弹窗；可用性判断改用 `hasBlockingError` |

---

### 1. ViewModel 层：返回值透传

#### AxisViewModelCore::setAbsTarget()

```cpp
bool AxisViewModelCore::setAbsTarget(double target) {
    if (!m_axis) return false;
    return m_axis->setAbsTarget(target);  // Axis::setAbsTarget 返回 bool
}
```

#### AxisViewModelCore::setRelTarget()

```cpp
bool AxisViewModelCore::setRelTarget(double distance) {
    if (!m_axis) return false;
    return m_axis->setRelTarget(distance);  // Axis::setRelTarget 返回 bool
}
```

原来的 Core 方法内部也改为直接透传 `bool`，QtAxisViewModel 的 `Q_INVOKABLE bool setAbsTarget(double)` / `Q_INVOKABLE bool setRelTarget(double)` 签名本已匹配。

---

### 2. 新增 hasBlockingError：区分错误严重程度

```cpp
// AxisViewModelCore.h
bool hasBlockingError() const;   // 仅 Modal 类错误阻断操作

// AxisViewModelCore.cpp
bool AxisViewModelCore::hasBlockingError() const {
    if (!m_orchestrator || !m_orchestrator->hasError())
        return false;
    
    // 只有 Modal 级别的 Blocking 错误才阻断用户操作
    auto vmError = translate(m_orchestrator->lastError());
    return vmError.isValid() && vmError.category() == ErrorCategory::Modal;
}
```

> **设计原则**：
> - **Inline 错误**（如超限位）：仅表示当前操作被拒绝，不锁死 UI，用户修正输入后可继续
> - **Modal 错误**（如急停、通讯中断）：严重故障，阻断所有操作直到清除
> - `hasBlockingError()` 仅对 Modal 错误返回 `true`

#### QtAxisViewModel Q_PROPERTY

```cpp
// QtAxisViewModel.h — 已有声明，无需修改
Q_PROPERTY(bool hasBlockingError READ hasBlockingError NOTIFY errorChanged)

// QtAxisViewModel.cpp
bool QtAxisViewModel::hasBlockingError() const {
    return m_core->hasBlockingError();
}
```

### 3. QML UI 层修改

#### 3.1 TargetSettingsPopup.qml：保存按钮 → 错误弹窗

```qml
// absTargetSaveButton.onClicked
var ok = viewModel.setAbsTarget(parseFloat(value))
if (!ok) {
    var errMsg = viewModel.errorMessage || "设置失败"
    errorDialog.errorText = errMsg
    errorDialog.open()
    return  // ← 不关闭 Popup
}
root.close()
```

新增 `errorDialog` Dialog 组件，用 `errorText` 属性动态显示错误信息。

#### 3.2 ActionControlBlock.qml：NumPad onConfirmed → 错误弹窗

```qml
// absTargetNumPad.onConfirmed
var ok = root.viewModel.setAbsTarget(parseFloat(value))
if (!ok) {
    var errMsg = root.viewModel.errorMessage || "设置失败"
    absTargetErrorDialog.errorText = errMsg
    absTargetErrorDialog.open()
}
```

新增 `absTargetErrorDialog` 和 `relTargetErrorDialog` 两个 Dialog 组件。

#### 3.3 ActionControlBlock.qml：可用性判断从 hasError → hasBlockingError

```qml
// 修改前
property bool isReadyForTrigger: ... && (!viewModel.hasError && viewModel.state <= 2 && !viewModel.isLoading)
property bool isReadyForSetTarget: ... && (!viewModel.hasError && viewModel.state <= 2)

// 修改后
property bool isReadyForTrigger: ... && (!viewModel.hasBlockingError && viewModel.state <= 2 && !viewModel.isLoading)
property bool isReadyForSetTarget: ... && (!viewModel.hasBlockingError && viewModel.state <= 2)
```

| 条件 | 修改前 | 修改后 | 影响 |
|------|--------|--------|------|
| 超限位拒绝后 | `hasError=true` → 按钮灰色 | `hasBlockingError=false` → 按钮可用 | ✅ 用户可重新输入 |
| 急停/通讯中断后 | `hasError=true` → 按钮灰色 | `hasBlockingError=true` → 按钮灰色 | 行为不变，符合预期 |

## 完整数据流

```
用户输入 target = -150.0（negLimit = -100.0）
    │
    ▼
QML NumPad.onConfirmed(value)
    │
    ├─ QtAxisViewModel::setAbsTarget(-150.0) → Q_INVOKABLE bool
    │     │
    │     └─ AxisViewModelCore::setAbsTarget(-150.0)
    │           │
    │           └─ Axis::setAbsTarget(-150.0)
    │                 │
    │                 ├─ 检查 target < negLimit → REJECT
    │                 └─ return false
    │
    ├─ return false
    │
    ▼
QML 检测 !ok
    │
    ├─ errorDialog.errorText = viewModel.errorMessage  // "AXIS_TARGET_OUT_OF_NEG_LIMIT"
    └─ errorDialog.open()  // 弹出 Modal 对话框
```

```
按钮可用性判断
    │
    ▼
isReadyForTrigger = !systemLocked
                 && !viewModel.hasBlockingError   // false（超限位是 Inline 错误）
                 && viewModel.state <= 2
                 && !viewModel.isLoading
    │
    └─ true → 按钮保持可用，用户可重新输入合法值
```

## 测试验证要点

1. 输入超出负限位的绝对目标 → 期望弹出错误对话框，NumPad 保持打开
2. 输入超出正限位的绝对目标 → 同上
3. 输入超出限位的相对距离 → 同上
4. 错误弹窗关闭后 → 按钮状态恢复正常可用（不为灰色）
5. 修正为合法值后 → 正常关闭 NumPad，target 正确设置
6. 发生急停/通讯中断等 Modal 错误时 → 按钮保持灰化锁定（不回归）
